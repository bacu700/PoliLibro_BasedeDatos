2.1. Modelo Relacional de Bases de Datos.

El Modelo Relacional es el paradigma más utilizado en la actualidad para la gestión y modelado de datos. Propuesto originalmente por Edgar F. Codd en 1970, se basa en la teoría matemática de conjuntos y en la lógica de predicados para organizar la información en tablas independientes pero interconectadas entre sí.
Este modelo permite representar la realidad del negocio de una manera matemática, formal y estructurada, garantizando que el acceso y la manipulación de la información se realice de forma consistente, segura y eficiente a través de lenguajes estandarizados como SQL.

El estudio del modelo relacional abarca cinco pilares esenciales que permiten entender cómo se estructuran y controlan los datos:

  • Estructura y características fundamentales de las tablas y atributos.
  • Operaciones lógicas y algebraicas que apoyan el modelo.
  • Mecanismos de integridad mediante Llaves Primarias y Foráneas.
  • Representación avanzada de relaciones n-arias y recursivas.
  • Aplicación práctica de estos elementos en un modelo de datos integrado.

2.1.1. Estructura y características del modelo relacional de bases de datos

La estructura central del modelo relacional es la relación, conocida comúnmente en la práctica como una tabla. Una base de datos relacional consiste exclusivamente en una colección de estas relaciones interconectadas.
El analista y el diseñador de bases de datos deben comprender las propiedades rígidas que posee este modelo para asegurar que los datos almacenados mantengan un orden lógico estricto. Cada elemento del modelo tiene una denominación matemática formal y un equivalente práctico dentro del software de bases de datos.
Utilizando este enfoque, se eliminan las ambigüedades en el almacenamiento y se facilita que tanto los desarrolladores como los sistemas de consulta interactúen de forma predecible con la información.


Las características y componentes fundamentales de una relación (tabla) son los siguientes:

Componentes Clave de una Relación

Tuplas (Filas / Registros): Representan cada uno de los elementos individuales u objetos que forman parte de la tabla. Cada tupla es un conjunto de datos que corresponden a una misma entidad y es única dentro de la relación; no pueden existir dos tuplas idénticas.

Atributos (Columnas / Campos): Representan las propiedades, características o cualidades de la entidad que se está modelando. Cada atributo tiene un nombre único en la tabla y describe un dato específico de la tupla.

Dominios: Es el conjunto de valores válidos y atómicos (indivisibles) que un atributo puede adoptar. Por ejemplo, el dominio para un atributo "Edad" podría ser el conjunto de números enteros positivos entre 1 y 120.


Figura 9. Estructura y Componentes de una Relación


Existen propiedades críticas que toda tabla relacional debe cumplir sin excepción: el orden de las tuplas y de los atributos no afecta en absoluto el significado de los datos; cada intersección entre una fila y una columna debe contener exactamente un único valor atómico (no se permiten listas ni arreglos internos); y finalmente, no pueden existir columnas con el mismo nombre dentro de una misma tabla.
Estas restricciones son las que dotan al modelo de su robustez matemática y permiten que los motores de bases de datos modernos optimicen las consultas a gran velocidad de manera transparente para el usuario.

2.1.2. Operaciones que apoyan el modelo relacional

Para manipular, consultar y extraer información útil de una base de datos relacional, el modelo se apoya en el Álgebra Relacional. Se trata de un conjunto de operaciones matemáticas que toman una o más relaciones como entrada y producen una nueva relación como resultado, sin modificar las tablas originales.

Operaciones Fundamentales del Álgebra Relacional

  1. Selección (Sigma - σ): Permite filtrar filas. Selecciona un subconjunto de tuplas que cumplen con una condición o predicado específico.
  2. Proyección (Pi - π): Permite filtrar columnas. Selecciona ciertos atributos de una tabla y descarta los demás, eliminando duplicados si los hubiera.
  3. Unión (∪): Combina las tuplas de dos tablas distintas. Ambas tablas deben ser compatibles, es decir, tener el mismo número de columnas y dominios idénticos.
  4. Diferencia de Conjuntos (−): Devuelve las tuplas que están en la primera tabla pero que no aparecen en la segunda tabla.
  5. Producto Cartesiano (×): Combina todas las tuplas de la primera tabla con todas las tuplas de la segunda tabla, creando todas las permutaciones posibles.
  6. Reunión (Join - ⨝): Es la operación más crucial en la práctica. Combina tuplas de dos o más relaciones basándose en una condición de emparejamiento (generalmente vinculando una Llave Primaria con una Llave Foránea).

Figura 10. Operaciones de Selección, Proyección y Join

Estas operaciones teóricas constituyen la base de lo que el lenguaje SQL ejecuta en la realidad cuando escribimos sentencias como SELECT, WHERE y JOIN, permitiendo cruzar grandes volúmenes de datos con precisión matemática.

2.1.3. Llave primaria, Llave Foránea e Integridad de bases de datos relacionales


La consistencia y la veracidad de los datos dentro de un sistema dependen por completo de los mecanismos de restricción y de las llaves que se definan en la estructura. Sin ellas, los datos podrían duplicarse o perder su coherencia lógica, convirtiendo a la base de datos en una fuente de información errónea.

Para interconectar las tablas de manera segura, el modelo relacional implementa dos conceptos operativos fundamentales:
La Llave Primaria (Primary Key - PK) es un atributo o conjunto mínimo de atributos que identifica de forma única e inequívoca a cada tupla dentro de una tabla. No puede haber dos filas con la misma PK y ningún componente de la PK puede quedar vacío (NULL).
La Llave Foránea (Foreign Key - FK) es un atributo en una tabla cuyo valor debe coincidir obligatoriamente con la Llave Primaria de otra tabla (o ser completamente nulo). Es el mecanismo físico que se utiliza para establecer los enlaces y relaciones entre los diferentes registros de la base de datos.

Reglas Generales de Integridad

  • Integridad de Entidad: Establece que ninguna llave primaria puede aceptar valores nulos (NULL), garantizando que cada registro siempre pueda ser identificado.
  • Integridad Referencial: Asegura que si existe una llave foránea, su valor debe corresponder obligatoriamente a una llave primaria válida y existente en la tabla de origen, evitando los "registros huérfanos".
  • Integridad de Dominio: Restringe los valores que puede tomar un atributo a aquellos que pertenezcan a su tipo de dato, rango o restricciones específicas previamente configuradas.

2.1.4. Relaciones n-arias y Relaciones recursivas


En el diseño del Modelo Relacional, la mayoría de los vínculos ocurren entre dos entidades (relaciones binarias). Sin embargo, la complejidad de las reglas de negocio a menudo exige representar escenarios donde intervienen múltiples entidades simultáneamente o donde una entidad se relaciona consigo misma.

Cuando nos enfrentamos a estas situaciones especiales, el modelo aplica las siguientes estructuras:
Las Relaciones n-arias involucran a tres o más entidades al mismo tiempo (por ejemplo, una relación ternaria entre Médico, Paciente y Medicamento para registrar una receta). En el modelo relacional, estas relaciones no se pueden conectar directamente; requieren la creación de una nueva tabla intermedia que hereda las llaves primarias de todas las entidades participantes como llaves foráneas.
Las Relaciones recursivas (o reflexivas) ocurren cuando una entidad se relaciona con otra instancia de sí misma. Un ejemplo típico es una tabla de Empleados donde un empleado es jefe de otros empleados. Para resolver esto, la misma tabla aloja una Llave Foránea que apunta y hace referencia a la Llave Primaria de su propia estructura.

Consideraciones para Relaciones Especiales

  • Identificación del grado: Determinar con precisión cuántas entidades participan en la regla de negocio para evitar fragmentar una relación n-aria en múltiples binarias incorrectas.
  • Atributos descriptivos: Las tablas intermedias surgidas de relaciones n-arias pueden contener sus propios atributos, como fechas, cantidades o estados del vínculo.
  • Roles en recursión: En las relaciones recursivas es fundamental asignar nombres claros al atributo de la llave foránea (por ejemplo, id_supervisor apuntando a id_empleado) para distinguir el rol que juega cada registro.

Al aplicar correctamente estas estructuras avanzadas, el diseñador garantiza que las dependencias lógicas complejas del mundo real queden perfectamente plasmadas en el esquema físico, impidiendo la pérdida de contexto en las consultas SQL multitabla.

2.1.5. Aplicación de los elementos anteriores en Modelos Relacionales

La consolidación de un Modelo Relacional requiere integrar todos los conceptos previos (tablas, llaves, restricciones e integridades) en un esquema unificado. Este proceso transforma las reglas de negocio abstractas en un plano lógico definitivo y funcional para el sistema de información.

  1. Mapeo de Entidades a Tablas: Cada conjunto de objetos del negocio se consolida como una relación física con sus respectivas columnas y filas.

  2. Asignación Inequívoca de PKs: Se asegura que cada tabla cuente con un identificador único que controle la integridad de la entidad.

  3. Establecimiento de Vínculos mediante FKs: Se trazan las uniones lógicas entre tablas, garantizando que los registros relacionados sigan de forma estricta las reglas de integridad referencial.

Esta visión integrada actúa como el puente definitivo hacia la etapa de diseño y normalización de la base de datos.


2.2 Diseño de BDs relacionales transformando el Modelo conceptual en Modelo Relacional.

2.2.1. Proceso de normalización

La normalización es una técnica matemática y lógica aplicada al modelo relacional para asegurar que la base de datos sea eficiente, esté libre de redundancias y protegida contra anomalías de inserción, actualización o borrado de datos. Consiste en pasar los datos por una serie de reglas conocidas como Formas Normales.

Etapas del Proceso de Normalización

  • Primera Forma Normal (1FN) - Atomicidad: Exige que todos los atributos de una tabla contengan valores atómicos (indivisibles) y que no existan grupos repetitivos ni listas de valores dentro de una sola celda.
  • Segunda Forma Normal (2FN) - Dependencia Funcional Completa: Cumpliendo la 1FN, exige que todos los atributos que no forman parte de la llave primaria dependan por completo de toda la llave primaria, y no de una parte de ella (aplica principalmente para llaves compuestas).
  • Tercera Forma Normal (3FN) - Dependencia No Transitiva: Cumpliendo la 2FN, exige que las columnas que no son llaves primarias dependan directamente de la llave primaria y no a través de terceras columnas intermedias.

2.2.2. Conversión de cardinalidad a posición de llaves primarias y foráneas

Al transformar un modelo conceptual (como un Diagrama Entidad-Relación) al modelo relacional, las cardinalidades dictan exactamente en qué lugar físico deben ubicarse las llaves para conectar las tablas de forma correcta:

  • Relaciones de Uno a Muchos (1:N): La regla general establece que la Llave Primaria del lado "Uno" se copia y se coloca como Llave Foránea (FK) en la tabla del lado "Muchos".
  • Relaciones de Muchos a Muchos (N:M): No pueden representarse directamente con una llave foránea simple. Se requiere crear una nueva Tabla Intermedia (o tabla de unión) cuyas llaves primarias combinadas correspondan a las llaves primarias de las dos tablas originales.
  • Relaciones de Uno a Uno (1:1): La Llave Primaria de una de las tablas se coloca como Llave Foránea en la otra tabla. La elección de cuál tabla recibe la FK suele depender de cuál entidad tiene una participación obligatoria en la relación.

2.2.3. Aplicación de características del modelo relacional

Como paso final para consolidar el diseño lógico, cada atributo de las tablas resultantes debe recibir sus especificaciones físicas definitivas, asegurando el control total sobre el comportamiento de los datos:

  • Tipo de Dato y Longitud: Determina la naturaleza de la información (VARCHAR para textos especificando su tamaño máximo, INT o DECIMAL para datos numéricos, DATE/DATETIME para marcas de tiempo).
  • Característica de Nulos (NULL / NOT NULL): Define de forma estricta si un campo puede quedar vacío o si es obligatorio capturar un valor al insertar un registro.
  • Integridad de Dominio: Restricciones que validan que el dato ingresado pertenezca a un rango o lista de valores específicos antes de ser guardado en el disco.
  • Integridad Referencial: Configuración de las acciones en cascada (ON DELETE / ON UPDATE: CASCADE, RESTRICT o SET NULL) que dictan cómo reaccionará la base de datos si se elimina o modifica un registro que está vinculado a otras tablas.
