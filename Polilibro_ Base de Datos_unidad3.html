3.1 Lenguaje Estructurado de Consulta (SQL)

El Lenguaje Estructurado de Consulta (SQL, por sus siglas en inglés Structured Query Language) es el estándar universal para la definición, manipulación y control de bases de datos relacionales. A diferencia de los lenguajes de programación imperativos, SQL es un lenguaje declarativo, lo que significa que el usuario especifica qué datos desea obtener en lugar de instruir paso a paso cómo recolectarlos.

En el entorno profesional de las Tecnologías de la Información, SQL actúa como la interfaz definitiva entre las aplicaciones de software y los motores de bases de datos. Su dominio permite a los ingenieros y administradores gestionar eficientemente volúmenes masivos de información, garantizando la integridad y la velocidad de acceso a los datos del negocio.

El estudio formal de SQL e implementación física se divide en cuatro grandes bloques operativos dentro de esta unidad:

  • Antecedentes históricos, características estructurales y ventajas de su adopción.
  • Diseño físico mediante el Lenguaje de Definición de Datos (LDD).
  • Mecanismos de seguridad, vistas y el Lenguaje de Control de Datos (LCD).
  • Extracción y manejo de información con el Lenguaje de Manipulación de Datos (LMD).

3.1.1. Antecedentes, características y ventajas del SQL

Los orígenes de SQL se remontan a la década de 1970 en los laboratorios de IBM, donde Donald Chamberlin y Raymond Boyce desarrollaron una primera versión llamada SEQUEL (Structured English Query Language), diseñada para implementar el modelo relacional formulado por Edgar F. Codd. Posteriormente, el lenguaje evolucionó y se comercializó masivamente por compañías precursoras en sistemas gestores de bases de datos.

Entre las características fundamentales de SQL destaca su base matemática robusta apoyada en el álgebra relacional, su sintaxis cercana al idioma inglés y su capacidad para operar sobre conjuntos de registros de manera simultánea en lugar de procesar fila por fila de forma manual.

La adopción de SQL proporciona ventajas competitivas críticas para cualquier arquitectura de datos moderna:

  • Portabilidad: El código SQL escrito para un motor específico puede adaptarse con mínimos cambios a otros sistemas gestores del mercado.
  • Aislamiento de datos: Separa de forma estricta la estructura lógica de los datos de cómo se almacenan físicamente en los discos de almacenamiento.
  • Optimización automática: El motor de la base de datos cuenta con un optimizador que decide el camino más rápido para ejecutar las consultas complejas de manera transparente para el usuario.

En conclusión, comprender los fundamentos lógicos y las ventajas del lenguaje SQL es un requisito indispensable para los ingenieros que diseñan la persistencia de datos en aplicaciones modernas.

3.1.2. Estándares de SQL

Para evitar la fragmentación del mercado y asegurar la compatibilidad entre el software de diferentes proveedores, el Instituto Nacional Estadounidense de Estándares (ANSI) y la Organización Internacional de Normalización (ISO) formalizaron a SQL como un estándar oficial. El primer estándar oficial se publicó como SQL-86, estableciendo las bases comunes del lenguaje.

A lo largo de los años, el estándar ha evolucionado de manera continua para incorporar nuevas capacidades técnicas a través de revisiones clave como SQL-92 (que estandarizó las operaciones JOIN), SQL:1999 (que introdujo expresiones regulares y disparadores), hasta las especificaciones modernas que dan soporte nativo a estructuras de datos XML, objetos JSON y funciones analíticas avanzadas.

Para ejemplificar cómo se estructuran los componentes del estándar dentro de un proyecto técnico, consideremos las distintas subdivisiones funcionales que componen la especificación oficial y que todo motor de base de datos comercial o de código abierto debe implementar.

En este escenario normativo se identifican las siguientes áreas de cumplimiento: el núcleo básico (Core), que define las características mínimas obligatorias que debe tener un motor para llamarse compatible con SQL, y los módulos de extensiones opcionales, que abarcan tipos de datos avanzados, soporte multimedia y conectividad remota.

El cumplimiento de estas normas garantiza un proceso de desarrollo estructurado e independiente del proveedor de software elegido, protegiendo la inversión tecnológica de las organizaciones frente a migraciones de servidores.

3.2 Diseño físico de Bases de Datos

El diseño físico representa la etapa de implementación técnica real donde los diagramas lógicos se transforman en estructuras físicas residentes en el servidor. En esta fase, el ingeniero interactúa directamente con el motor de base de datos (DBMS) para crear los contenedores de datos que soportarán la operación de las aplicaciones de software.

Durante el diseño físico, el uso preciso de la sintaxis y de las restricciones es crítico para evitar fallos de rendimiento y asegurar que el motor bloquee de manera automática la inserción de datos corruptos o incompletos.

3.2.1. Lenguaje de Definición de Datos (LDD) del SQL

El Lenguaje de Definición de Datos (LDD o DDL por sus siglas en inglés Data Definition Language) es el subconjunto de sentencias de SQL diseñado específicamente para la creación, modificación y eliminación de las estructuras que alojan los datos en el servidor, tales como tablas, índices, vistas y esquemas completos. Las sentencias más importantes del LDD son CREATE, ALTER y DROP.

El ciclo del LDD se inicia con el análisis del diccionario de datos y avanza a través de la ejecución de scripts estructurados en el servidor de desarrollo, asegurando que las restricciones lógicas queden perfectamente plasmadas en el almacenamiento físico del sistema.

3.2.2. Creación de tablas y aplicación de cláusulas NULL, NOT NULL, DEFAULT, PRIMARY KEY, FOREIGN KEY y CONSTRAINT

La creación de tablas es la acción fundamental del diseño físico y se realiza mediante la sentencia CREATE TABLE. Durante este proceso, cada columna debe ser perfectamente tipificada y configurada con cláusulas específicas que controlan de forma estricta las reglas de integridad de la base de datos.

Cláusulas de Configuración e Integridad

  • NULL / NOT NULL: Determina si una columna acepta la ausencia de datos (NULL) o si es estrictamente obligatorio capturar un valor al registrar una fila (NOT NULL).
  • DEFAULT: Asigna un valor predeterminado automático a la columna en caso de que el usuario no envíe un dato explícito durante la inserción.
  • PRIMARY KEY: Establece formalmente el identificador único de la tabla, impidiendo valores duplicados y nulos de forma automática en esa columna.
  • FOREIGN KEY: Configura el enlace referencial hacia la llave primaria de otra tabla, garantizando que no existan registros huérfanos.
  • CONSTRAINT: Permite asignar nombres explícitos y personalizados a las restricciones de la tabla, facilitando su posterior mantenimiento y la identificación de errores en la aplicación.

3.2.3. Modificación de características de objetos y eliminación de Objetos

Los entornos de software evolucionan constantemente, lo que exige que la estructura física de la base de datos se adapte a los nuevos requerimientos del negocio sin necesidad de destruir las tablas existentes ni perder los datos ya almacenados en producción.

Para modificar objetos de la base de datos, el LDD provee la sentencia ALTER (por ejemplo, ALTER TABLE), la cual permite agregar nuevas columnas, eliminar campos obsoletos, cambiar tipos de datos o modificar restricciones activas. Por otro lado, cuando un objeto ya no es necesario dentro del esquema, se utiliza la sentencia DROP (por ejemplo, DROP TABLE) para eliminar permanentemente su estructura y todo su contenido del disco del servidor.

3.3 Seguridad de datos y privilegios de usuarios

De acuerdo con los estándares internacionales de seguridad en Tecnologías de la Información, la protección del activo más valioso de una organización —sus datos— debe gestionarse de forma estricta dentro del propio motor de base de datos, asegurando que solo el personal y los procesos autorizados tengan acceso a la información confidencial.

Las reglas de seguridad aplicadas al modelo físico definen los mecanismos que controlan el acceso a las tablas, restringiendo operaciones críticas de acuerdo con los roles asignados a los usuarios de la empresa.

3.3.1. Uso de vistas

Una Vista es una tabla virtual basada en el resultado de una consulta SQL predefinida. No almacena datos físicos de forma independiente; en su lugar, actúa como un filtro de seguridad dinámico sobre las tablas reales (tablas base).

Las vistas permiten simplificar consultas complejas ocultando las uniones de tablas al usuario final, y actúan como un excelente mecanismo de seguridad al permitir que un usuario consulte ciertas columnas específicas de una tabla sin otorgarle acceso directo ni visibilidad sobre el resto de los campos confidenciales.

3.3.2. Lenguaje de Control de Datos (LCD) del SQL

El Lenguaje de Control de Datos (LCD o DCL por sus siglas en inglés Data Control Language) es el subconjunto de sentencias de SQL encargado de administrar la seguridad, el acceso y los permisos de los usuarios sobre los objetos de la base de datos. Sus componentes centrales son las sentencias GRANT y REVOKE.

A través de estas sentencias, el Administrador de la Base de Datos (DBA) puede implementar un control de acceso basado en roles, asegurando un entorno audituable y protegido contra accesos no autorizados.

3.3.3. Privilegios aplicables a las tablas

Los privilegios definen las acciones específicas que un usuario tiene permitido ejecutar sobre un objeto de la base de datos. Al aplicar privilegios sobre las tablas, el administrador puede conceder permisos detallados utilizando la sentencia GRANT o retirarlos con REVOKE de forma selectiva.

Los privilegios estándar aplicables a las tablas incluyen SELECT (permiso para leer datos), INSERT (permiso para añadir filas), UPDATE (permiso para modificar registros existentes) y DELETE (permiso para eliminar renglones). Esto asegura que, por ejemplo, un sistema de facturación pueda registrar ventas pero tenga estrictamente prohibido borrar el historial financiero.

3.4 Manejo de información de las Bases de Datos

Una vez que las estructuras físicas han sido creadas y aseguradas en el servidor, el sistema entra en su fase operativa principal: la interacción con los datos reales generados por los usuarios del sistema de información.

3.4.1. Lenguaje de Manipulación de Datos (LMD)

El Lenguaje de Manipulación de Datos (LMD o DML por sus siglas en inglés Data Manipulation Language) es el subconjunto de comandos SQL que permite a los usuarios y aplicaciones gestionar la información contenida dentro de las tablas previamente creadas. A diferencia del LDD, el LMD no altera la estructura del esquema, sino únicamente los registros internos.

3.4.2. Inserción, actualización y eliminación de renglones

Las operaciones básicas de manipulación de datos se ejecutan mediante tres sentencias fundamentales que conforman el ciclo operativo de los registros:

  • INSERT: Añade nuevos renglones o registros a una tabla respetando los tipos de datos y restricciones de integridad de las columnas.
  • UPDATE: Modifica los valores de uno o varios atributos en los renglones existentes. Exige el uso cuidadoso de la cláusula WHERE para evitar alterar accidentalmente toda la tabla.
  • DELETE: Remueve físicamente uno o más renglones de una tabla basándose en una condición específica dictada por la cláusula WHERE.

3.4.3. Consultas simples y multitabla utilizadas para consultas

La recuperación de información se realiza mediante la sentencia SELECT, el comando más potente y utilizado de SQL. Las consultas simples extraen datos de una sola tabla aplicando filtros lógicos, ordenamientos y agrupamientos básicos.

Por otro lado, las consultas multitabla permiten unificar y cruzar datos distribuidos en diferentes estructuras físicas mediante la cláusula JOIN (como INNER JOIN o LEFT JOIN), vinculando llaves primarias con foráneas para construir reportes y respuestas de negocio integradas.

3.4.4. Funciones de columnas y funciones escalares

SQL enriquece la recuperación de datos mediante el uso de funciones integradas en el motor que realizan cálculos avanzados directamente en el servidor:

  • Funciones de Columnas (o de Agregación): Operan sobre un conjunto de valores de una columna completa para devolver un único resultado resumido. Ejemplos típicos son SUM() (total), AVG() (promedio), COUNT() (conteo de registros), MIN() y MAX().
  • Funciones Escalares: Operan de forma individual sobre cada valor de una celda y devuelven un valor transformado por cada fila procesada, como funciones de manipulación de texto (UPPER(), SUBSTRING()), cálculos matemáticos absolutos o manipulación y formato de fechas.
