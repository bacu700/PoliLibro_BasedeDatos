VISTA (VIEW)

Una vista es una consulta que se presenta como una tabla (virtual no existe físicamente) a partir de un conjunto de tablas en una base de datos relacional. Las vistas tienen la misma estructura que una tabla: filas y columnas, pero no existe como conjunto de valores de datos almacenados en una base de datos. La instrucción se basa en una consulta (select).
          CREATE VIEW nom_vista AS(
          SELECT campos a consultar
          FROM nombres de las tablas
          WHERE condición);

ÌNDÍCE (INDEX)

Los índices son usados para acelerar el proceso de consultas, resultando un alto desempeño, son similares a índices de libros de texto. En los libros de texto, si usted necesita ir a un capítulo en particular, usted va al índice, encuentra el número de página del capítulo y va directamente a esa página. Sin índices, el proceso de encontrar su capítulo deseado habría sido muy lento.
Un índice permite el acceso de forma DIRECTA y RÁPIDA a los registros de una tabla
Para crear índices empleamos la instrucción "create index".
La sintaxis básica es la siguiente:
create TIPODEINDICE index NOMBREINDICE on TABLA(CAMPO);
TIPODEINDICE indica si es agrupado (clustered) o no agrupado (nonclustered). Si no especificamos crea uno no agrupado.
Independientemente de si es agrupado o no, también se puede especificar que sea "unique", es decir, no haya valores repetidos. Si se intenta crear un índice unique para un campo que tiene valores duplicados, SQL Server no lo permite.

Ejemplo:
Se desea crear un índice agrupado único para el campo Id_Autor de la tabla Autor:
CREATE unique clustered INDEX I_departamento__Clave_Dep ON departamento(Clave_Dep);

Para identificar los índices fácilmente, podemos agregar un prefijo al nombre del índice, por ejemplo "I" y luego el nombre de la tabla y/o campo.

Ahora se desea crear un índice no agrupado para el campo Nombre_Departamento de la tabla de departamento:
CREATE nonclustered index I_departamento_Nombre_Departamento ON departamento(Nombre_Departamento);

CREATE CLUSTERED INDEX (Carrera, Turno, Semestre) ON Alumno

DML

Este lenguaje consta de un conjunto de instrucciones que nos permiten modificar el estado de los datos que residen en las tablas, respetando las restricciones de integridad.
Cualquiera de las siguientes instrucciones se pueden ejecutar para uno o varios registros de la tabla:

  • INSERT para agregar nuevos registros
  • DELETE para borrar registros
  • UPDATE para modificar valores de los registros
  • SELECT para efectuar cualquier consulta
INSERT

Esta instrucción nos permite AGREGAR nuevos registros a una tabla.
Al ingresar los datos de cada registro debe tenerse en cuenta la cantidad y el orden de los campos.
La sintaxis básica y general es la siguiente:
insert into NOMBRETABLA (NOM_CAMPO1, ..., NOM_CAMPOn) values (VALORCAMPO1, ..., VALORCAMPOn);

Se usa insert into, luego el nombre de la tabla, se detalla los nombres de los campos entre paréntesis y separados por comas.
Por último en la cláusula values se colocan los valores para cada campo, también entre paréntesis y separados por comas.

Por ejemplo:
insert into departamento (Clave_Dep, Nombre_Departamento, Gerente) values (01, ‘Informática’, ‘Mariano García’);

Los datos ingresados que corresponden a cadenas de caracteres (varchar o char) se colocan entre comillas simples.

Existe otra forma más sencilla para ingresar datos:
insert into departamento values (02, ‘Ventas’, ‘Luis Pérez’);

Para verificar que los datos fueron correctamente insertados en una tabla, se usa la instrucción select:
select * from departamento;

Ejemplos de las funciones agregadas que se utilizan en el select

La función sum() retorna la suma de los valores que contiene el campo especificado.
Ejemplo: Si queremos saber la cantidad total de libros que tenemos disponibles para la venta, debemos sumar todos los valores del campo cantidad, de la tabla de libros, la instrucción quedaría de la siguiente:
SELECT sum(cantidad) FROM libros;

Para averiguar el valor máximo o mínimo de un campo se usan las funciones max() y min() respectivamente.
Por ejemplo se desea saber cuál es el mayor precio de todos los libros:
SELECT max(precio) FROM libros;

La función avg() retorna el valor promedio de los valores del campo especificado.
Ejemplo: se desea saber el promedio del precio de los libros referentes a "PHP":
SELECT avg(precio) FROM libros WHERE titulo like '%PHP%';

Ahora se puede comprender porque estas funciones se denominan "funciones de agrupamiento", porque operan sobre conjuntos de registros, no con datos individuales.

GROUP BY

Las funciones de agregado solas producen un valor de resumen para todos los registros de un campo. Podemos generar valores de resumen para un solo campo, combinando las funciones de agregado con la cláusula group by, que agrupa registros para consultas detalladas.

Queremos saber la cantidad de libros de cada editorial, podemos tipear la siguiente sentencia:
SELECT count(*) FROM libros WHERE editorial='Planeta';

Existe otra forma utilizando la cláusula group by:
SELECT editorial, count(*)
FROM libros
GROUP BY editorial;

La instrucción anterior solicita que muestre el nombre de la editorial y cuente la cantidad agrupando los registros por el campo "editorial". Como resultado aparecen los nombres de las editoriales y la cantidad de registros para cada valor del campo.

Para saber el máximo y mínimo valor de los libros agrupados por editorial:
SELECT editorial, max(precio) AS mayor, min(precio) AS menor FROM libros GROUP BY editorial;

Para calcular el promedio del valor de los libros agrupados por editorial:
SELECT editorial, avg(precio) FROM libros GROUP BY editorial;

SELECT editorial, count(*) FROM libros WHERE precio<30 GROUP BY editorial;

ORDER BY

Con esta instrucción se puede ordenar el resultado de un select para que los registros se muestren ordenados por algún campo, para ello usamos la cláusula order by.
La sintaxis básica es la siguiente:
SELECT * FROM nombretabla ORDER BY campo;

Por ejemplo, se desea recuperar los registros de la tabla libros ordenados por el título:
SELECT * FROM libros ORDER BY titulo;

Aparecen los registros ordenados alfabéticamente por el campo especificado.

DCL

Este lenguaje consta de un conjunto de instrucciones que nos sirven para administrar privilegios:

  • GRANT: Autoriza un privilegio sobre un objeto
  • REVOKE: Retira un privilegio ya autorizado
  • DENY: Negar un privilegio ya autorizado

Privilegios sobre tablas y vistas a los usuarios:

  • INSERT para agregar nuevos registros
  • DELETE para borrar registros
  • UPDATE para modificar valores de los registros
  • SELECT para efectuar cualquier consulta
  • INDEX para accesar de forma directa y rápida
  • ALTER modificar campos de una tabla
GRANT

Da privilegios sobre un objeto a un usuario
GRANT privilegio(s)
ON nombre del objeto
TO usuario
WITH GRANT OPTION

Ejemplos para dar privilegios al usuario USERID1 sobre la tabla de departamento:
GRANT insert, update, select, delete
ON departamento
TO USERID1

GRANT insert, select
ON departamento
TO USERID1

GRANT *
ON departamento
TO USERID1

La cláusula with grant option delega el grant específico (privilegios y objeto) a usuarios para que estos también lo ejecuten.
GRANT insert, delete
ON departamento
TO USERID1
WITH GRANT OPTION

REVOKE

Retira los privilegios sobre un objeto a un usuario
REVOKE privilegio(s)
ON nombre del objeto
FROM usuario
CASCADE

REVOKE insert, select
ON departamento
FROM USERID1

REVOKE *
ON departamento
FROM USERID1

La cláusula CASCADE retira en cascada los privilegios otorgados previamente
REVOKE insert, select
ON departamento
FROM USERID1
CASCADE

También se puede usar el DENY para negar privilegios a los usuarios
DENY insert, select
ON departamento
TO USERID1

PRIMERA FORMA NORMAL (1FN)

Una relación esta en primera forma normal (1FN) si:
A) Los dominios de todos los atributos de R son atómicos
En otras palabras, la 1FN prohíbe a un campo contener más de un valor de su dominio de columna. Un dominio es atómico si se considera que los elementos de ese dominio son unidades indivisibles.
Los atributos compuestos, como el atributo dirección con los componentes Calles y Ciudad, tiene dominios no atómicos
B) Todas las tablas deben tener una clave primaria (PK).
C) Una tabla no debe tener atributos que acepten valores nulos

SEGUNDA FORMA NORMAL (2NF)

La segunda forma normal (2NF) es una forma normal usada en normalización de bases de datos y fue definida originalmente por E.F. Codd en 1971.

Una relación está en 2FN si y solo si:

  • 1.-Está en 1NF.
  • 2.-Todos los atributos fuera de la llave primaria son funcionalmente dependientes de la misma de manera completa.

ANOMALÍAS EN RELACIONES 2NF

Una relación 2FN puede presentar anomalías de almacenamiento si cualquiera de sus no-claves depende transitivamente de la clave primaria.

Se dice que una no-clave depende transitivamente de la clave primaria si es funcionalmente dependiente de otra no-clave, en otras palabras, depende indirectamente de la clave principal.
