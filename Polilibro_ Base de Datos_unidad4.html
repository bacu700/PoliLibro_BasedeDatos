Principios

Modelo de almacenamiento mas simple.
Los elementos se almacenan siguiendo una clave ejemplo:
{Usuario123: “Paco”} donde Usuario123 seria la CLAVE y Paco el VALOR.
Acceso directo por clave.
Podríamos tomar la clave como la ID de una tabla relacional solo que al seleccionarla nos daría todo el valor.
Sin esquema fijo.
Operaciones limitadas.
No es posible realizar consultas especializadas como JOIN o filtros a las búsquedas.

Características

  • Soporte para tipos de datos complejos
    • El valor puede ir desde un numero entero, texto, numero binario, o inclusive un archivo tipo JSON
  • Claves clasificadas
    • Un gestor de base de datos tipo clave-valor puede ordenar automáticamente las claves para facilitar la búsqueda.
  • No es estructurada
    • Al no usar tablas no necesariamente tiene que seguir un orden estricto:
Clave Valor
Usuario123 “Paco”
TotalCarrito 1234
ArticulosFavoritos <1,45,23>

Se puede observar que la misma BD tiene String, Int y un array de Ids de otra posible BD y es perfectamente valido.

Software:

  • Redis
  • Amazon DynamoDB
  • Riak
  • RocksDB
  • etcd
  • Memcached
Operaciones

Al no ser una base de datos especializada en consultas complejas, no cuenta con tantas operaciones como una base de datos relacional u otras NoSQL. Este modelo se limita principalmente a 3 operaciones básicas:

  • Get (Lectura): Recupera el valor asociado a una clave específica de forma directa y rápida.
  • Put / Set (Escritura/Actualización): Inserta una nueva clave con su respectivo valor o actualiza el contenido si la clave ya existe.
  • Delete (Eliminación): Remueve por completo la clave y su valor asociado del sistema de almacenamiento.

Conclusiones

  • Son el modelo de almacenamiento más simple.
  • Ofrecen flexibilidad en los tipos de valores pero carecen de un esquema estructurado.
  • Tienen operaciones limitadas, por lo que no son adecuadas para consultas complejas.
  • Son una opción ideal para escenarios de alto rendimiento donde se prioriza la rapidez de acceso sobre la complejidad de las consultas.
¿Qué es una base de datos documental?

Es una base de datos que puede almacenar y consultar datos en documentos tales como:

Lo mas común es usar JSON o BSON este segundo siendo una forma binaria del primero

Principios de las Bases de Datos Documentales

Modelo orientado a documentos

  • Almacenan datos en formato de documentos (usualmente JSON, BSON, XML).
  • Cada documento representa una unidad de datos completa y autosuficiente.

Sin esquema rígido (schema-less)

  • Los documentos pueden tener estructuras distintas dentro de la misma colección.

Escalabilidad horizontal

  • Alta disponibilidad y particionado automático (sharding)
Elementos de las Bases de Datos Documentales

Una base de datos documental está conformada por 3 elementos:

  • Base de Datos
  • Colecciones
  • Documentos (generalmente JSON, BSON o XML)

Documentos JSON

JSON viene de JavaScript Object Notation, es un formato ligero, fácil de escribir y leer por los humanos además de simple interpretación y creación para las maquinas.

Lo que lo volvió el lenguaje predilecto para el intercambio de datos.

Estructura de JSON

Está conformado por 2 estructuras:

  • Una colección de nombre/valor
  • Lista ordenada de valores

Un objeto es todo aquello que esté dentro de las “{}” (llaves).

El nombre siempre será un STRING.

El valor puede tener distintos tipos de dato:

  • Numérico: como en id y age
  • STRING: como en name, email, gender, city, country y language
  • Binario (Booleano): como en isActive o newsletter
  • Arrays: como en roles

Características de las Bases de Datos Documentales

  • Flexible: Ya que no necesita de un esquema fijo para el almacenamiento de la información.
  • Rápido rendimiento: Optimizado para operaciones masivas de lectura y escritura.
  • Escalabilidad horizontal: Diseñado de forma nativa para distribuirse eficientemente en clústeres.
  • Soporte para replicación: Alta disponibilidad y tolerancia a fallos mediante la copia de nodos.
  • Potente sistema de consultas: Capacidades avanzadas para filtros, frameworks de agregación y búsquedas anidadas.

Operaciones de la Base de Datos Documentales

Insertar un documento:

Para agregar un único documento a una colección, se utiliza el método insertOne. Cabe destacar que para MongoDB es indiferente si las claves del nombre del atributo están entre comillas ("") o no en la sintaxis de la consola:

db.nombre_de_coleccion.insertOne({objeto JSON})

Insertar varios documentos:

Si se requiere realizar la inserción de múltiples registros en una sola operación, se pasan los objetos estructurados dentro de un arreglo de JavaScript utilizando insertMany:

db.nombre_de_coleccion.insertMany([{Objeto JSON 1}, {Objeto JSON 2}, ... , {Objeto JSON n}])

Mostrar todos los documentos:

Para recuperar y visualizar todos los registros existentes dentro de una colección, empleamos el método find con un objeto de filtrado vacío. Esta instrucción funciona exactamente igual que un SELECT * FROM tabla en las bases de datos relacionales:

db.nombre_de_colección.find({})

Seleccionar en específico:

Para realizar una consulta filtrada por un criterio específico, colocamos la clave y el valor que deseamos hacer coincidir dentro del objeto de búsqueda. Esta instrucción funciona exactamente igual que un SELECT * FROM Usuarios WHERE username = 'Javier' en SQL:

db.nombre_de_colección.find({username: "Javier"})

Editar un campo existente del documento:

Para modificar el valor de un atributo que ya se encuentra registrado en el documento, se utiliza el método updateOne junto con el operador atómico $set. El primer objeto localiza el documento y el segundo define los cambios:

db.nombre_de_colección.updateOne({nombre_campo: "valor_a_buscar"}, {$set: {campo_a_editar: "nuevo_valor"}})

Editar un campo inexistente del documento (Agregar nuevo campo):

En las bases de datos documentales, si el atributo que se pasa dentro del operador $set no existe previamente en el documento encontrado, MongoDB lo creará e insertará dinámicamente en ese registro sin alterar la estructura de los demás documentos de la colección:

db.nombre_de_colección.updateOne({nombre_campo: "valor_a_buscar"}, {$set: {campo_inexistente: "valor_del_nuevo_campo"}})

¿Qué ocurre si al editar no agregamos el parámetro de búsqueda y lo dejamos general?

A diferencia de SQL, donde omitir la condición WHERE en un UPDATE modifica todos los registros de la tabla, en MongoDB los métodos estándar protegen la colección por defecto:

  • Si utilizas updateOne({}, {$set: {...}}) con un objeto de búsqueda vacío, MongoDB no arrojará un error, pero solo modificará el primer documento que encuentre en la colección.
  • Si tu intención real es aplicar el cambio de manera general a absolutamente todos los registros de la colección, debes utilizar explícitamente el método updateMany pasando el filtro vacío:

db.nombre_de_colección.updateMany({}, {$set: {campo: "nuevo_valor_general"}})

¿Qué ocurre si al editar no agregamos el parámetro de búsqueda y lo dejamos general?

Editar varios documentos:

Para modificar múltiples registros que cumplan con una misma condición al mismo tiempo, se utiliza el método updateMany. Todos los documentos que coincidan con el parámetro de búsqueda serán actualizados con los valores especificados en el operador $set:

db.nombre_de_colección.updateMany({parámetro_de_busqueda}, {$set: {nombre_campo: "valor_a_añadir"}})

Comúnmente no queremos editar todos los campos, por eso usamos el parámetro de búsqueda:

El primer objeto funciona como un filtro (equivalente al WHERE de SQL) para asegurar que la modificación se aplique única y exclusivamente a los documentos que cumplen con dicha condición, protegiendo la integridad del resto de los registros en la colección.

db.nombre_de_colección.updateMany({parámetro_de_busqueda}, {$set: {nombre_campo: "valor_a_añadir"}})

Eliminar un documento:

Para suprimir un único registro de la colección, se utiliza el método deleteOne. El sistema buscará el primer documento que coincida con el criterio especificado en el parámetro de búsqueda y lo borrará permanentemente:

db.nombre_de_colección.deleteOne({parámetro_de_busqueda})

Eliminar varios documentos:

Para borrar múltiples registros de forma simultánea, se utiliza el método deleteMany. Todos los documentos dentro de la colección que coincidan con el criterio establecido en el parámetro de búsqueda serán eliminados permanentemente:

db.nombre_de_colección.deleteMany({parámetro_de_busqueda})

Operadores

Existen distintos operadores lógicos que podemos usar, como $and, $or y $nor, los cuales adquieren exactamente el mismo funcionamiento y comportamiento que las compuertas lógicas tradicionales de su mismo nombre.

Estos operadores se integran directamente en el parámetro de búsqueda de cualquier operación (como find, updateMany o deleteMany) y nos ayudan a realizar filtros y búsquedas muchísimo más específicas mediante la evaluación de múltiples condiciones.

Sintaxis general:

A diferencia de los filtros simples, los operadores lógicos reciben como valor un arreglo (denotado por corchetes []), donde cada elemento es un objeto JSON que representa una condición individual separada por comas:

db.nombre_de_colección.nombre_de_operación({$operador: [{parámetro_de_busqueda_1}, {parámetro_de_busqueda_2}, ... , {parámetro_de_busqueda_n}]})

Operador $and:

Este operador evalúa que todas las condiciones especificadas dentro del arreglo se cumplan simultáneamente. En este caso, buscará única y exclusivamente a los usuarios que se llamen "Dave" Y que, al mismo tiempo, tengan exactamente la edad de 30 años:

db.nombre_de_colección.find({$and: [{name: "Dave"}, {age: 30}]})

Operador $and:

Este operador evalúa que todas las condiciones especificadas dentro del arreglo se cumplan simultáneamente. En este caso, buscará única y exclusivamente a los usuarios que se llamen "Dave" Y que, al mismo tiempo, tengan exactamente la edad de 30 años:

db.nombre_de_colección.find({$and: [{name: "Dave"}, {age: 30}]})

db.nombre de colección.nombre de operación({$operador:[parámetros de búsqueda (separados por coma)]})

Conclusiones

  • Flexibilidad estructural: Las bases de datos documentales permiten almacenar información en documentos autosuficientes, lo que les otorga una enorme flexibilidad al no depender de un esquema rígido o fijo.
  • Alta disponibilidad: Ofrecen de manera nativa una excelente escalabilidad horizontal y una sólida tolerancia a fallos mediante mecanismos de replicación distribuidos.
  • Eficiencia operativa: Su modelo orientado a documentos facilita operaciones de lectura y escritura sumamente rápidas, acompañadas de un sistema potente para ejecutar consultas avanzadas y agregaciones.
  • Simplicidad en el desarrollo: Permiten gestionar el ciclo de vida completo de los datos y realizar operaciones CRUD (Crear, Leer, Actualizar, Eliminar) de forma directa y sencilla mediante objetos JSON/BSON.
